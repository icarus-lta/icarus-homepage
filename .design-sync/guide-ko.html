0. 먼저 알아야 할 네 가지

다크 전용

거의 검정에 가까운 우주 배경 하나만 씁니다. 라이트 테마는 없고, 색을 반전시키면 안 됩니다.

액센트는 아이스 블루 하나

강조색은 ice 계열 하나뿐입니다. 다른 색을 새로 만들지 않습니다.

영문 카피가 기본

컴포넌트 기본 문구는 모두 영어입니다. 한글 카피는 요청이 있을 때만 넣습니다.

섹션이 배경을 스스로 칠함

모든 섹션 컴포넌트는 자기 배경을 가집니다. 직접 만든 블록은 bg-space-950 위에 올려야 흰 글씨가 읽힙니다.

서체는 본문 Pretendard, 숫자·라벨은 IBM Plex Mono입니다. 둘 다 스타일시트에서 CDN으로 불러오므로 따로 설치할 것이 없습니다.

회사 설명: ICARUS LTA는 고도 20 km 성층권에 머무르는 무인 비행선을 만듭니다.

1. 페이지에 붙이기

React가 먼저 로드된 페이지에 아래 두 줄만 추가합니다. 프로바이더나 래퍼 컴포넌트는 없습니다.

<link rel="stylesheet" href="styles.css">
<script src="_ds_bundle.js"></script>
  • styles.css 한 파일만 링크하면 됩니다. 토큰·폰트·컴포넌트 스타일(_ds_bundle.css)을 모두 @import 합니다.
  • 이 스타일시트가 페이지 기본값도 정합니다 — 배경 bg-space-950, 본문색 text-mist, Pretendard, 부드러운 스크롤.
  • 컴포넌트는 window.IcarusDS.*에 들어옵니다. 마운트는 호스트 페이지의 React 루트가 아니라 별도 노드(예: <div id="ds-root">)에 하세요. 두 트리가 충돌합니다.
// 컴포넌트 꺼내 쓰는 방법
const { AltitudeScrollSection } = window.IcarusDS;
ReactDOM.createRoot(document.getElementById('ds-root')).render(<AltitudeScrollSection />);
SiteHeader는 페이지 위에 떠 있습니다. SiteHeader는 기본이 position="fixed"입니다. Hero는 이걸 전제로 만들어져 사진이 헤더 밑까지 올라갑니다(일부러 그렇게 둔 것이니 여백을 넣지 마세요). PageHero는 반대로 헤더를 피할 상단 여백을 자기가 가지고 있습니다. 그 둘이 아닌 다른 컴포넌트를 첫 섹션으로 쓸 때만 pt-32를 직접 넣습니다.

2. 홈페이지 조립 순서

기본 홈페이지는 이 순서로 쌓습니다.

const { SiteHeader, Hero, AltitudeScrollSection, EnduranceScrollSection,
        MissionGrid, RoadmapTimeline, ContactCTA, SiteFooter } = window.IcarusDS;
<div className="overflow-x-clip">
  <SiteHeader />
  <Hero />                       {/* 사진과 첫 애니메이션 사이에는 아무것도 넣지 않습니다 */}
  <AltitudeScrollSection />      {/* 스크롤 연동 3단: 궤도만 → 직접 하강 → ICARUS 중계 */}
  <EnduranceScrollSection />     {/* 스크롤 연동: 주간 태양충전 / 야간 방전 / 수년간 체공 */}
  <MissionGrid />
  <RoadmapTimeline />
  <ContactCTA />
  <SiteFooter />
</div>
페이지를 overflow-x-hidden으로 감싸지 마세요. 그 클래스는 감싼 요소를 스크롤 컨테이너로 바꿔 버리고, 그러면 position: sticky가 조용히 동작을 멈춥니다. 스크롤 애니메이션 두 개가 그냥 지나가 버리는데 에러는 하나도 안 납니다. 반드시 overflow-x-clip을 쓰세요. 중간에 overflow-hidden이 들어간 부모가 하나라도 있으면 같은 증상이 납니다.
좌우 여백은 페이지 전체가 하나로 통일되어 있습니다. 모든 띠는 화면 끝까지 꽉 차고, 그 안의 내용만 공통 여백선에 맞춥니다. 그 여백이 window.IcarusDS.containerClass(w-full mx-auto px-6 md:px-10 lg:px-16 2xl:px-24)입니다. 직접 만드는 띠에도 이 클래스를 넣으면 헤더·히어로 제목·사진과 같은 선에 맞습니다. max-w-6xl 같은 좁은 칸으로 다시 가운데 정렬하지 마세요 — 넓은 화면에서 글자만 가운데 몰려 사진과 어긋나 보입니다.
위 목록이 홈페이지 전부입니다. 확정된 와이어프레임의 6개 섹션(히어로 · 스크롤 애니메이션 2개 · 임무 · 로드맵 · 마무리) 그대로이며, 여기에 섹션을 더하지 않습니다. 히어로 사진과 첫 애니메이션 사이도 비워 둡니다 — 수치 띠도, 라벨도, 설명 문장도 넣지 않습니다. StatBar와 TechCards는 여전히 제공되지만 자리는 서브페이지·캠페인 페이지이지 홈페이지가 아닙니다.
두 애니메이션 섹션은 제목이 프레임 위에 옵니다. 제목이 그 장면을 설명하는 대제목이고, 그 아래 전체 폭 프레임에서 애니메이션이 재생됩니다. 옆에 나란히 두지 마세요. AltitudeScrollSection에는 eyebrow를 붙이지 않습니다 — 히어로 사진 바로 아래 오는 페이지의 두 번째 대제목이라 단독으로 섭니다.
히어로 사진은 선으로 끊기지 않습니다. 아래쪽 224~288px가 space-900(바로 다음 섹션의 남색)으로 서서히 녹아들어 이음매가 보이지 않습니다. 히어로 바로 밑 섹션의 배경색을 바꾸면 이 그라데이션도 같이 바꿔야 합니다.

서브페이지(Info, Technology, Career, Contact)는 같은 껍데기에서 Hero 자리에 PageHero를 넣고, 그 아래 Section 블록들을 쌓은 뒤 ContactCTA와 SiteFooter로 닫습니다.

섹션 (sections)

4. 모션

  • 등장 — 무엇이든 Reveal로 감싸면 스크롤 진입 시 페이드되며 올라옵니다. 한 줄에 여러 개일 때는 delay={0|100|200}로 시차를 줍니다. TechCards, MissionGrid, RoadmapTimeline은 내부에서 이미 적용하고 있습니다.
  • 스크롤 연동 장면 — useScrollProgress()가 {ref, progress}를 돌려줍니다. ref를 높이가 큰 섹션에 붙이고 progress(0~1)로 원하는 것을 움직입니다. ramp(progress, from, to)는 그 구간만 잘라 이징한 0~1 값을 줍니다. 두 스크롤 섹션이 이 방식으로 동작합니다 — 높이가 큰 <section> 안에 sticky top-0 h-screen 장면이 들어 있는 구조입니다.
  • 스크롤 장면을 직접 만들 때 두 가지 — sticky 박스는 정확히 h-screen이어야 합니다(화면보다 높은 sticky 요소는 절대 고정되지 않습니다). 그리고 위쪽 조상 중 overflow-hidden이 하나도 없어야 합니다(2번 항목의 빨간 상자 참고).
  • 한 프레임 고정 — 두 스크롤 섹션은 progress={0..1}를 받으면 스크롤을 따라가지 않고 그 지점에서 멈춥니다. 정적 목업용이며, 실제 페이지에서는 쓰지 마세요.
  • 절제 — 투명도와 짧은 이동만, duration-500/duration-700, ease-out. 반복 애니메이션은 비행선의 느린 animate-float 하나뿐입니다.

5. 스타일링: Tailwind CSS v4 + 브랜드 팔레트

직접 쓰는 글루 마크업은 아래 클래스로만 스타일하세요. 인라인 스타일이나 새 CSS는 쓰지 않습니다.
